# CLAUDE.md, Drs Rego website

Read this before touching anything. It records the rules, the stack and the decisions so nobody has to repeat them.

## What this project is

The public website for Drs Rego (FFAM Holdings Pty Ltd trading as Drs Rego, ABN 66 690 668 529), an Australian medical registration, compliance and GP recruitment consultancy run by Faisal Al-Falah. Live at https://drsrego.com.au on Netlify. Two audiences: internationally trained doctors, and the Australian general practices that employ them. Enquiry-only business model.

Faisal is not a developer. Explain every significant change in plain English, work in small steps, and never batch twenty changes before asking for review.

## Stack and build

- Static site generated by Eleventy 3 (Nunjucks templates, markdown for jobs and posts). Source in `src/`, output in `_site/` (gitignored).
- `npm run build` = `node scripts/validate-content.js && eleventy`. `npm test` = build plus `node scripts/check-site.js`.
- Netlify builds on push using `netlify.toml` (build command `npm test`, publish directory `_site`, Node 22). The post-build checker therefore runs on every deploy too.
- Forms are Netlify Forms. They only work while hosted on Netlify.
- No CSS framework, no client-side framework, no CMS. Vanilla JS in `src/assets/js/`.
- Local preview: build, then serve `_site` (`.claude/launch.json` runs `python -m http.server 8734 --directory _site`).

See `DEPLOY.md` for how deployment works and `CONTENT.md` for adding jobs, posts and case studies.

## Hard content rules (compliance requirements, not style)

Apply to every word on the site, in templates, meta tags, structured data and docs.

1. **No pricing anywhere, on any page.** Enquiry-only. No "from $X", no ranges, no indication.
2. **No outcome guarantees and no turnaround times.** Never say a registration "takes 8 weeks" or that we can "get you registered". Ahpra, the AMC, the Colleges and Medicare make those decisions.
3. **No immigration or visa advice, and no implication that we provide it.** If visas or sponsorship come up anywhere, the copy says it is referred to a registered migration agent.
4. **No regulatory fact stated without a source and a date.** Anything about DPA, MMM, section 19AA, section 19AB, PESCI or supervision must link to health.gov.au or ahpra.gov.au (the Medical Board pages live at medicalboard.gov.au, an Ahpra site, and count) and carry a "last verified" date. If not certain, write `[VERIFY: …]` and Faisal will check it. Do not guess and do not fill gaps from memory.
5. **No em dashes anywhere in copy.** Use commas, colons or full stops.
6. **Australian English throughout.** Organisation, specialise, programme, practise (verb).
7. **The correct department name is Department of Health, Disability and Ageing.** Not "Health and Aged Care".
8. **Every candidate-facing form carries a privacy link and an unsubscribe path.**

The validator (`scripts/validate-content.js`) enforces what it can: em dashes, `[VERIFY:` markers in published files, the wrong department name, and dollar amounts in markdown. It fails the build with a plain-English message.

## Regulatory sourcing workflow

- Source URLs and verification dates live in `src/_data/regulatory.json`. Templates read from it, so one edit updates the eligibility block and every FAQ answer that uses that source.
- Only record a URL after it has been opened and confirmed live. Otherwise write `[VERIFY: what is needed]` as the value; the build refuses to publish until it is resolved.
- Posts carry their own `last_verified` date and a `sources` list in front matter.
- Starter posts ship as `draft: true` with `[VERIFY:]` markers. They cannot be published until every marker is resolved.

## Content and URL rules

- Existing URLs are preserved exactly (`/doctors.html`, `/clinics.html`, `/about.html`, `/contact.html`, `/privacy.html`, `/terms.html`, `/thank-you.html`). New sections use directory URLs (`/jobs/`, `/jobs/<slug>/`, `/insights/`, `/insights/<slug>/`, `/register-your-interest/`, `/request-a-doctor/`).
- Nav labels: For Doctors (doctors.html), For Practices (clinics.html), Jobs, Insights, About, Contact. Home is the logo on desktop and the first item in the mobile menu.
- "Ask us" on a job page is the main conversion point. It links to `/contact.html?topic=eligibility&job=<slug>`.
- Job pages with `status: filled` or `closed` stay online with a banner, drop out of the sitemap and carry no JobPosting structured data.
- No invented job adverts, testimonials or case studies. Publishing fabricated records is never acceptable.
